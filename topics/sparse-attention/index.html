稀疏注意力：谁和谁该算？

标准注意力让每个 token 与几乎所有历史 token 交互，代价随长度平方增长。稀疏注意力的关键不是换一套新公式，而是规定（或学习）一张允许连边的图：每个 query 只对少数 key 做 softmax。本页按 Longformer、BigBird、Sparse Transformer、DeepSeek NSA 等原文，把图案、操作步骤与现代可训练方案讲透。

改连边，不改 softmax 本质 常见复杂度 O(L·w) / O(#块) 工业主流：局部 + 全局 / 块路由

01先建立直觉

把注意力想成一张分数表：行是「正在提问的位置」（query），列是「可以被查阅的历史位置」（key）。格子里先填相似度，再经 softmax 变成权重，最后用这些权重去加权对应的 value，得到该行的输出向量。

全注意力（Full Attention）在因果语言模型里，几乎等于：只要不看未来，这张表的下三角全部填满。长度 L 时，有效格子大约是 L²/2。L=4k 已经不小；到 64k、128k 时，即便 Flash Attention 已经把「怎么搬显存」优化得很好，你仍然要为海量 query–key 配对付出计算。长上下文推理里，注意力往往能占掉绝大部分延迟——NSA 技术报告也强调：64k 解码时 softmax 注意力可占整体延迟的 70–80%。

稀疏注意力的出发点很朴素：softmax 之后，真正拿到大权重的位置通常很少（邻近词、标点、开头的 sink、检索头盯住的远处句子）。那为什么还要为「注定接近 0」的格子付钱？于是我们改规则：

一句话：对每个 query 位置 t，只允许它与子集 S(t) 里的 key 计算分数并做 softmax；集合外视为不存在（分数 −∞）。输出仍是加权求和 value，只是邻居变少了，复杂度从「跟 L 成平方」变成「跟 |S(t)| 成正比」。

图 1 · 行=query、列=key。绿色局部、橙色全局、蓝色随机/选中块；浅灰为因果禁止的未来。

读图时请抓住两件事：① 白色/浅色不是「算了再扔掉」，理想实现里这些格子根本不算；② 不同论文的差别，几乎都是「S(t) 怎么定」——固定图案、随机、还是模型学习路由。

02数学上在做什么

标准因果注意力（Vaswani et al.；NSA 报告式 (1)(2)）对位置 t 写：

o_t = Attn(q_t, k_1:t, v_1:t) α_t,i = exp(q_tᵀ k_i / √d) / Σ_j exp(q_tᵀ k_j / √d) o_t = Σ_i α_t,i · v_i

稀疏版只是把求和与归一化限制在允许集 S(t) ⊆ {1…t}：

α_t,i = exp(q_tᵀ k_i / √d) / Σ_{j∈S(t)} exp(q_tᵀ k_j / √d) (仅 i∈S(t)) o_t = Σ_{i∈S(t)} α_t,i · v_i
容易误解的点：稀疏之后，softmax 分母变小了，所以允许集里的权重会被「重新放大」。这不是 bug，而是设计：你把概率质量从删掉的边上，重新分配给留下的边。因此图案必须保证信息仍能（多跳）传到远处，否则模型会「看不见」长程依赖。

这也解释了为什么 Longformer / BigBird 都强调局部窗口不够——必须加全局节点或随机边，让图在理论上连通；BigBird 甚至证明：在一定条件下，带随机边的稀疏注意力仍是序列函数的万能近似器。

03主流稀疏图案（按原文）

3.1 滑动窗口（Local / Sliding Window）

每个 token 只看最近 w 个位置：S(t) = {t−w, …, t}（再加因果约束）。复杂度约 O(L·w)。Mistral 等现代 LLM 直接把 sliding window 写进架构；FlashAttention-2 也提供 window_size，在 kernel 里跳过窗外的 key 块。

优点：实现简单、对 GPU 友好、局部语法/搭配很强。缺点：距离超过 w 的信息必须靠多层「接力」传递，层数不够时远距依赖会丢。Longformer 原文把「扩张窗口 / 全局 token」当作补救。

3.2 Longformer：局部 + 全局 token

Longformer（Beltagy et al., 2020）的核心图案是：

  • 滑动窗口负责局部上下文；
  • 再选少量 global tokens（如 [CLS]、任务相关位置），它们可以 attend 全序列，也被全序列 attend。

直觉：把文档里的「枢纽车站」设成全局站，普通站只连邻近站——全网仍可达，边数却近似线性。这是今天「工业长文本」最常见的骨架之一：90% 局部 + 少量全局。

想把这一段吃透？看专页详解：Longformer 局部 + 全局注意力（含四种图案图、对称全局、两套 QKV、任务怎么设全局位）。

3.3 BigBird：局部 + 全局 + 随机块

BigBird（Zaheer et al., 2020）在窗口与全局之外，再加 随机稀疏边（常以块为单位）。随机边缩短了图上的平均路径长度，理论性质更漂亮。工程上它推动了「块稀疏」表示：不是每个 token 各选邻居，而是按 block 决定整块是否参与，方便用块矩阵核。

展开读：BigBird 详解专页（三块积木图、小世界路径、ITC/ETC、块稀疏、与 Longformer 对照）。

3.4 Sparse Transformer：固定步长 / 跨步图案

Sparse Transformer（Child et al., 2019）更早提出用固定 stride、局部块等模式把自注意力变稀疏，让生成模型能吃更长序列。今天纯 LLM 预训练里「手写 stride」已不如窗口+全局流行，但「用固定图案换线性复杂度」的思路一脉相承。

3.5 学习式路由 / Top-k / 块选择

固定图案省事，但「谁重要」其实依赖输入。于是有 Reformer（LSH 分桶）、Routing Transformer、各种 Top-k，以及 2025 的 NSA（Native Sparse Attention）：先压缩成粗粒度块，再选重要块做细粒度注意力，并保留滑动窗口。路由更灵活，也更吃实现——选得太碎会破坏连续内存访问，Flash 类 kernel 用不上。

04操作怎么落地（算子四步）

图 2 · 稀疏注意力的标准操作流水线。关键是第 1 步的图案要能映射成「跳过计算」，而不是「算完再 mask」。

  1. 构造图案：掩码或索引表 为每个 query（或每个 query 块）生成允许的 key 下标 S(t)，或块级 bitmask。PyTorch 教学实现常在 logits 上对禁止位加 −inf；高性能实现则直接不加载这些 key。
  2. 只对允许位置算 QKᵀ 朴素做法：先算完整矩阵再 mask——简单但浪费。正确方向：gather 子集，或块稀疏 GEMM（xFormers / Triton）。与 Flash 结合时：整块被 mask 掉的 key tile 直接不读入 SRAM。
  3. 在允许集上 Softmax 归一化分母只含 S(t)。窗口图案每行宽度固定，kernel 最好写。学习式 Top-k 则每行宽度为 k，但索引可能不连续。
  4. 对允许的 V 加权求和 与 dense 相同，只是 V 被限制在子集。块稀疏下：小块 Q×K → softmax → ×V → 累加，循环块——这正是 Flash tiling 的朋友。
训练时还要注意反向：梯度只流经允许边。若图案含离散采样（某些哈希/聚类选 token），可能切断梯度——NSA 报告批评过「推理期才稀疏、训练不可微」的方案。可训练稀疏要末要么固定图案，要么让选择过程可导/用直通估计，并尽量块对齐以便反传也能走高效 kernel。

05NSA：可训练的现代稀疏（DeepSeek 技术报告）

NSA（Native Sparse Attention, arXiv:2502.11089）把问题拆成两件必须同时成立的事：① 硬件上真的加速（理论稀疏不等于墙钟时间下降）；② 训练期原生稀疏（不要只在推理剪枝，以免偏离预训练轨迹）。

图 3 · NSA 对每个 query 并行三条注意力路径，再门控融合（对照报告 Figure 2）。

5.1 三路分别解决什么

Compression 压缩

把连续 token 块用可学习映射压成块级 K/V，用粗粒度表示抓住长程语义轮廓，大幅减少要参与注意力的「键」数量。

Selection 选择

在重要块上保留细粒度 token，避免「只看摘要」丢失关键细节。按块选而不是按零散 token 选，利于连续内存与 Tensor Core。

Sliding Window

强制保留最近局部上下文——语言建模里邻近依赖极强，窗口是便宜且必要的底线。

门控融合

三路输出用输入相关的门控 g∈[0,1] 加权相加，模型可学习何时更信全局摘要、何时更信精选细节。

5.2 为什么强调「块」与算术强度

报告花大量篇幅讨论：很多稀疏法在 MHA 上「看起来省了」，但到 GQA/MQA 上，同一组 query heads 各自选不同 KV，并集一扩大，内存带宽优势就消失。NSA 的策略是让稀疏模式与分组共享的 KV 布局兼容，并用块级算子提高算术强度，让优化目标在 prefill（算力界）与 decode（带宽界）两侧都站得住。

实验叙述上：在 27B 骨干、260B token 预训练设定下，NSA 在通用、长上下文与推理评测上平均不弱于 Full Attention，并在 64k 的 decode/前向/反向阶段都给出显著加速——这是「原生训练的稀疏」想证明的故事。

06工程里怎么用（2024–2026）

6.1 架构层：混合堆叠

很多长上下文模型并不让每一层都全连接，而是：多数层用窗口 / 线性注意力（如 Mamba、GDN、KDA），每隔几层插一层全注意力或稀疏全局层。稀疏在这里是架构超参，不是推理开关。

6.2 框架接口

  • Hugging Face：attention_mask；Mistral 系 sliding_window；Longformer 的 local+global 位置。
  • FlashAttention-2：window_size=(w_left, w_right) 融合局部注意力。
  • PyTorch SDPA：在支持时走 flash/mem-efficient 后端；复杂稀疏掩码可能回退。

6.3 推理：KV cache 上的「另一种稀疏」

还有一类方法训练仍用全注意力，解码时剪 cache（H2O、StreamingLLM sink、SnapKV）：省的是存与读，不一定省 prefill 算力。它和「前向计算稀疏」互补：一个管算哪些，一个管缓存留哪些。

6.4 和 Flash 的关系（务必分清）

稀疏决定注意力图上哪些边存在；Flash决定存在的边如何在 GPU 内存层次上被高效计算。最佳实践往往是：块稀疏图案 + Flash 风格 tiling；NSA 类方法在选中的密集子块上再跑高效 attention kernel。

08名词解释

稀疏注意力

每个 query 只与 key 子集计算注意力，避免完整 L×L 连边。

sparsity pattern / mask

规定哪些 (query,key) 允许计算的图案或掩码。

sliding window

只保留最近 w 个位置的局部注意力。

global token

可与全序列双向（或单向）连接的枢纽位置。

block sparse

以块为单位允许/禁止注意力，便于 GPU 块矩阵核。

Top-k / routing

按分数或路由器动态选择参与注意力的 key/块。

attention sink

少数位置稳定吸引大量注意力质量；常作流式生成的锚点。

NSA

DeepSeek 提出的原生可训练稀疏注意力：压缩+选择+窗口。

算术强度

计算量/访存量之比；决定算子是算力界还是带宽界。

KV cache 剪枝

解码时丢弃或合并缓存条目，属推理期稀疏。
